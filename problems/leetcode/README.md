# LeetCode problems

Each problem keeps the official statement, solution, and tests together in a
folder prefixed with LeetCode's public problem number:

```text
problems/leetcode/<number>-<problem-slug>/
├── description.md
├── <problem-slug>.ts
└── <problem-slug>.test.ts
```

Create a scaffold with:

```bash
npm run new-leetcode -- "https://leetcode.com/problems/two-sum/"
```

The script also accepts a title such as `"Two Sum"` or a slug such as `two-sum`.
It fetches official metadata, converts the statement to Markdown with examples
and constraints, and leaves the source and tests as generic stubs. Use the
`new-problem` skill to prepare the official signature and executable tests
without implementing the solution. Existing folders are never overwritten,
including legacy unnumbered folders.

Keep `description.md` focused on the problem. Put `// Time complexity: ...` and
`// Space complexity: ...` immediately above the exported solution function or
class. New scaffolds use TODO values until the solution is implemented.
